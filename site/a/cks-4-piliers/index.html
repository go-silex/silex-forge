Gate D3 · PROPOSED

ICP — qui on sert

Reco : primary = agence / boîte de services 5–50. Pourquoi pas solo d'abord : multi-user plus tôt, ACV install plus haut, lead magnet agences déjà prêt, preuve « service qui compose ».

Buyer vs user

Buyer (paie)

Dirigeant / associé fondateur. Veut levier d'équipe et signal AI-native — pas un 5ᵉ outil.

Users (vivent dedans)

Ops, delivery, collabs. Écrivent la Memory, lancent les skills, subissent l'Engine.

Segments

SegmentFitRôleEntrée
Agence / services 5–50 Service is the new product · multi-user · install 2,5–4,5k Primary Memory + Plugins + Engine light
Solopreneur / fondateur solo Live funnels · pack light · cash plus bas Secondary Memory + Plugins seed
Builder / vibe-coder Influence · talks MCP Influence Plugins + SSOT MCP
Silex interne Dogfood + preuve Dogfood Les 4 piliers

Beachhead

Horizontal services d'abord (agence com, consulting, studio, conseil) — même spine Memory/Plugins. Verticals santé/legal = archétypes brain-factory plus tard, pas le wedge com.

Jobs-to-be-done

Fonctionnel

  • Contexte client ne repart plus de zéro
  • Agents qui rangent / retrouvent / agissent
  • Process en skills versionnées, pas PDF morts

Émotionnel / social

  • Composer comme un produit sans perdre le sur-mesure
  • Moins de héros-mémoire dans l'équipe
  • Signal AI-native face aux pairs

Kill criteria (sales screen)

✕Refuse d'own les fichiers (tout dans un GPT Project) ✕« Range mon Drive » sans agents ✕Veut remplacer CRM/ERP ✕Deck stratégie only, zéro install

Journey 2 · Process Audit (Spark) × CKS

Le journey Spark Process Audit est le template delivery le plus proche d'un install brain structuré :

  1. Pre-sales → Signature → Kickoff — Memory : brief SSOT ; SSOT : Attio/Claap
  2. Onboarding leader + Atelier 1 — Memory : map business ; Plugins : forms Spark / SOP chat
  3. Post-atelier · ressources · pilotage — Engine : recovery insights ; Memory : scoping MVP / structure brain
  4. Construction MVP · ateliers · feedback tickets — Plugins + Engine debug loop sur Spark
  5. Roadmap — Memory décisions ; SSOT tickets run
Transfert CKS : remplacer « MVP produit client » par « vault + 4 piliers au bon niveau » dans le même squelette d'ateliers. Pattern déjà vu : Ulysse / Pauline (fichier cliquable + structure + espace).
