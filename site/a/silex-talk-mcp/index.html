MCP seul
Des capacités brutes
  • L'agent peut appeler tes outils.

Mémoire · 02

Quand utiliser quoi ?

01
Passage à lire / citer
Search si mots exacts · Vectoriel si question en langage naturel. C'est du lookup.
02
Structure, impact, chemin
Graphe. « De quoi X dépend ? » « Comment A est relié à B ? » Ce n'est pas de la similarité de texte.
03
Les deux (cas fréquent)
Graphe d'abord pour cadrer le sous-système · search/vecteurs ensuite pour lire le détail des nœuds touchés.
Anti-pattern
Tout en vecteurs = confondre « proche » et « relié ».

Mémoire · 04 · Identité

« Client » CRM = « Client » billing

D'un point de vue business, c'est la même entité du monde réel. Un graphe naïf en fait souvent deux nœuds sans lien — ou pire, les merge par hasard de label.

Ce qu'on ne fait pas
Fuzzy aveugle
  • Merger tous les labels proches.
  • Confondre homonymes code et entités métier.
  • Laisser le LLM inventer l'identité.
Ce qu'on gouverne
Glossaire + same_as
  • Nœud canonique Client.
  • Vues système reliées (same_as).
  • Review humaine sur l'alignement.
Règle
L'identité métier se décide — elle ne s'improvise pas.
19 / 26
Mémoire · 05 · Builder

Comment on ship le
graphe d'entreprise

01
Ontologie légère
6–10 types : Process, System, Entity, Role, Rule, Decision — pas un UML le jour 1.
02
Extraction contrainte
LLM avec schéma (nœuds nommés + relations typées) · tag EXTRACTED vs INFERRED · provenance obligatoire.
03
Coupler search + vecteurs
Chaque nœud pointe vers des chunks. Graphe pour naviguer, RAG pour citer.
04
Exposer en MCP
path · explain · query · get_entity — la machine traverse, l'humain cure.
